# Reproducibility

## Scope

The repository contains the active source path, version-controlled specifications, selected results, report figures, and checksum records. Raw data, trained model binaries, VecNormalize files, and large local outputs are excluded. The selected results are therefore inspectable from Git, while full reruns require local artifacts.

## Setup

Use the dependency files at the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

The same dependencies can be installed with `environment.yml` when Conda is preferred. Run commands from the repository root so the modules resolve their project-relative paths.

## Versioned Configs and Runtime Records

Use this distinction consistently:

- `configs/` contains version-controlled final configurations, specifications, manifests, checksums, and locked metadata included in Git.
- `outputs/configs/` contains local runtime-generated copies, environment snapshots, execution records, and artifact hashes.

The exact records for the main path are:

- Environment: `configs/environment/perishability_master_config.json`, `configs/environment/perishability_accounting_specification.json`, `configs/environment/perishability_financial_reward_specification.json`, and `configs/environment/pricing_env_operational_config.json`.
- Original PPO: `configs/ppo/ppo_operational_experiment_config.json` and `configs/ppo/ppo_input_artifact_hashes.json`.
- Balanced PPO: `configs/ppo/ppo_redesign_selected_model.json`, `configs/ppo/ppo_redesign_selected_model_hashes.json`, and `configs/ppo/ppo_validation_episode_manifest.csv`.
- DQN: `configs/dqn/final_locked_dqn_ensemble.json` and `configs/dqn/final_locked_dqn_ensemble_hashes.json`.
- Held-out evaluation: `configs/evaluation/final_test_evaluation_protocol.json`, `configs/evaluation/artifact_manifest.csv`, and `configs/evaluation/checksum_manifest.sha256`.

The runtime modules may read or write corresponding files under `outputs/configs/`; those local files capture the execution environment and artifact state for a particular run.

## Data and Artifacts

FreshRetailNet-50K raw parquet files are expected locally under the paths documented in `data/raw/README.md`. The main processed inputs are `data/freshretail/processed/freshretail_modeling_subset.parquet` and `data/freshretail/processed/freshretail_demand_recovered.parquet` when generated by the numbered scripts. Fitted response models and learned policy binaries are under local `outputs/models/` paths and are not included in the public repository.

## Execution Order

The numbered entry points are documented in `scripts/README.md`:

1. `scripts/01_prepare_freshretail_data.py`
2. `scripts/02_recover_stockout_demand.py`
3. `scripts/03_train_original_ppo.py`
4. `scripts/04_train_balanced_ppo.py`
5. `scripts/05_train_dqn.py`
6. `scripts/06_evaluate_locked_dqn_ensemble.py`
7. `scripts/07_run_final_baseline_ladder.py`

Steps 1-2 prepare data, steps 3-5 train models, and steps 6-7 evaluate or summarize existing artifacts. Training is not required to inspect the selected `results/` files and can be compute-intensive.

## Split Isolation

The data pipeline keeps episode construction inside train, validation, and test boundaries. The final comparison uses `outputs/manifests/high_risk_b_final_test_manifest.csv` when run locally and expects 60 held-out episodes. The locked test protocol is recorded in `configs/evaluation/final_test_evaluation_protocol.json`. The test manifest is not used to tune model hyperparameters or rule thresholds.

## Validation Checks

Non-training checks that can be run without model artifacts include:

```powershell
python -m compileall -q src scripts tests
pytest -q tests
```

Additional checks should validate Markdown relative links, referenced-file existence, CSV schemas, JSON parsing, configuration-path consistency, and checksum records. Model-dependent tests may skip when local raw data or model binaries are absent.

## Reproduction Limits

Exact numerical reruns depend on the local data version, fitted demand and response artifacts, model checkpoints, runtime versions, and recorded seeds. The repository's selected tables and figures preserve the reported conclusion, but they are not a substitute for the excluded local binaries and raw data.
